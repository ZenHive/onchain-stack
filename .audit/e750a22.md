## Findings

Seven findings; all seven addressed — four fixed in this commit, three filed as tasks
because each needs a decision rather than an edit.

### Fixed here

**1. `CLAUDE.md` / `AGENTS.md` claim a per-package credo override that does not exist.**
The consolidated-config paragraph says "`cartouche` and `onchain` still carry their own
`.credo.exs` on top of the root policy — verify whether that's an intentional per-package
override or leftover drift." Verified: neither does. All eight
`packages/<name>/.credo.exs` are symlinks to the root `.credo.exs` (`1a53f15` deleted the
real files; the note survived the commit that falsified it). The paragraph now states the
symlink fact, so a reader knows the root policy is the only place credo rules can change.

**2. Two stale edges in the `CLAUDE.md` / `AGENTS.md` dependency graph**, both falsified
inside this very range:
- `onchain → zen_websocket ~> 0.7.0` — actual is `~> 0.9.0`, raised by `28c9a2d` for the
  descripex 1.0 floor.
- `onchain_aave → sibling(:onchain_evm, "~> 0.5")` — actual is `~> 0.6`.

The section hedges itself ("this is a hint, not ground truth"), but a wrong hint costs
more than no hint; both corrected against the `mix.exs` files and confirmed by
`mix onchain.bounds` output.

**3. The `--summary-only` Open Item was carried as unverified — it is now measured.**
The item said the package-by-package migration's "completeness across all eight has not
been re-verified since the merge." It is 6 of 8: hieroglyph, cartouche, onchain,
onchain_evm, onchain_js and onchain_tempo still pass the flag; onchain_aave and
onchain_aerodrome have dropped it. The Open Item now names the six and points at task
9004 instead of asking the next reader to re-measure.

**4. `onchain_aerodrome` had no CHANGELOG entry for task 5001.** The `[Unreleased]`
section carried only the `docs/`-in-tarball fix. Task 5001 closed a finding the 0.1.0
entry explicitly records as open ("the `.reach.exs` layer gate does not yet enforce what
it documents, and forbids `bindings -> types`, which the layer table requires") and added
`test/reach_architecture_test.exs` — squarely the "notable change" the project's
after-every-task rule asks for. Added under `### Changed` and `### Added`.

Two stale code comments went with the doc fixes, same class:
- root `mix.exs` still described the root `.credo.exs` as "cartouche's policy verbatim —
  Phase 2 promotes it to the family-wide root policy" in the future tense; Phase 2
  happened.
- `shared/mix_helpers.exs` opens "Both gates shell out to scripts that live OUTSIDE this
  repo." Only one does now — see finding 5.

### Filed as tasks

**5. Task 9003 — `advisory_freshness/1` reaches into `~/_DATA/code/onchain-stack`, so
every other checkout skips the gate.** `shared/mix_helpers.exs` resolves the prover as an
absolute path into the canonical developer checkout. That was correct before 2026-08-27,
when `onchain-stack` was a separate coordination repo; `bin/advisory-freshness.sh` has
been a tracked file *in this repo* since the migration, two levels up from any package.
Any clone that is not literally `~/_DATA/code/onchain-stack` — the server mirror
`/data/postgresql/code/onchain-stack` that harness registers as this project's source
included — takes the `File.regular?/1` false branch and prints
`[skip] advisory-mirror freshness check: ... absent in CI`. The gate exists precisely
because `mix_audit` discards its own sync exit status and prints "No vulnerabilities
found" against a frozen database (mirego/mix_audit#61), so this is the anti-silent-green
gate being skipped. Not fixed inline: flipping it also decides whether `mix ci` inside a
harness worktree starts touching the shared advisory clone, which is a concurrency call,
not hygiene. The script itself needs nothing — it only ever operates on
`$MIX_AUDIT_ADVISORY_PATH` and never inspects its own checkout.

**6. Task 9004 — drop `--summary-only` from the six packages that still carry it.** The
flag is in ex_unit_json's `retry_disqualified_opts?/1` list, so it silently disables
retry-on-flaky *and* replaces assertion detail with a bare summary line. Mechanical, but
it is a six-package sweep with six serial `mix ci` runs behind it (never parallel — the
shared advisory clone).

**7. Task 9005 — the consolidated root `.mcp.json` reaches only cartouche's Tidewave.**
`f9d6102` merged eight per-package MCP configs into one; eight tidewave entries on eight
different ports could not survive that, and the survivor is `localhost:4013` = cartouche.
The other seven (hieroglyph 4006, onchain 4007, onchain_evm 4009, onchain_tempo 4010,
onchain_aave 4012, onchain_js 4028, onchain_aerodrome 4035) are unaddressable, and nothing
records that the entry is cartouche-specific. Either shape is defensible — eight named
entries, or one plus a documented convention — which is why this is a task and not an
edit; the current state is the one that is not, because it silently means "cartouche".

To hold the three, a root-scoped phase and bundle were added: `[phases.0] [monorepo] Root
tooling & gates` / `monorepo_root_gates`, with the matching `ROADMAP.md` marker block
(the renderer only emits into phases that already have one).
